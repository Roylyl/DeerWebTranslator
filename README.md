# DeerWebTranslator

## 使用方法

1. 克隆本仓库，或下载源码 ZIP 并解压。
2. 打开 Chrome 的 `chrome://extensions`，启用右上角的「开发者模式」。
3. 点击「加载已解压的扩展程序」，选择包含 `manifest.json` 的项目根目录。
4. 打开扩展的「设置」，选择供应商，输入你自己的 API Key，选择模型和目标语言并保存。本地 Ollama 通常无需 API Key。可点击「测试已保存的连接」检查配置；测试可能消耗少量 API 额度。
5. 打开普通网页，点击工具栏中的 DeerWebTranslator，再点击「翻译当前页面」。
6. 默认直接在原来的位置显示译文。扩展先处理当前视口及附近内容，滚动时自动补译。

运行扩展不需要安装 Node.js、npm 或执行构建命令。更新源码后，在扩展管理页点击「重新加载」，再刷新目标网页。首次安装前已经打开的页面也可能需要刷新。

如果项目目录被移动，请在扩展管理页从新目录重新加载。路径变化可能导致开发版扩展 ID 改变，旧设置不一定会自动迁移；如需重新配置 API Key，请在设置页手动输入，不要把设置导出到源码目录。

### 阅读与控制

- **仅译文**：默认模式。在原有文字节点上显示译文，保留页面元素、字号、布局样式和交互。
- **仅原文**：恢复原文并暂停派发新批次；已发出的请求可能完成并写入缓存。重新切回译文时复用已有结果。
- **双语**：短标签显示为 `English｜中文`。普通长段落保留原文，并在下方显示独立译文区域。导航和控件内的文字使用行内对照，避免插入块级区域。
- **停止翻译**：停止任务及后续滚动补译，尽力中止请求；已经显示的译文保留。中止请求不代表供应商一定不会计费。
- **重试失败部分**：只重发未成功的内容，已成功的段落不会跟随整页重新请求。任务停止后，如需继续，请点击「翻译当前页面」。
- **选中段落翻译／重译**：选中文字，在右键菜单选择「翻译／重译选中段落」。尚未开始翻译时只处理选中段落；已有任务时只强制重译选中的段落，其他译文保留。主动重译会绕过该段缓存，可能产生新的 API 用量。
- **快捷键**：`Alt + Shift + T` 开始翻译或切换原文／译文。可在 `chrome://extensions/shortcuts` 修改；快捷键冲突时请重新分配。
- **此网站**：可设为「手动翻译」「总是翻译」或「不自动翻译」。默认手动；只有明确选择「总是翻译」的站点会在后续打开时自动处理。规则按完整站点来源（协议、主机及端口）保存，不跨子域名共享。站点会记住双语／仅译文偏好；临时查看原文不会抹去它。
- **本页用量与快捷操作**：展开弹窗底部的信息区，查看本轮请求数、供应商实际返回的 token 用量、本地缓存复用和界面词典命中情况。
- **设置**：配置 API、模型、目标语言、技术领域、系统提示词及自定义术语表；测试已保存的连接或手动清除翻译缓存。

进度统计的是本轮已发现并进入处理范围的内容，不代表整张长网页已经预先翻译完毕。滚动到新的区域时，进度可能继续增长。

### 常见问题

- **改了源码但行为没变**：在 `chrome://extensions` 重新加载扩展，再刷新目标网页；旧内容脚本不会因磁盘文件变化自动替换。
- **错误页出现 `Extension context invalidated`**：通常是扩展重载、更新或停用后，旧网页脚本仍尝试使用已经失效的扩展连接，不是模型鉴权错误。本版统一处理同步异常和 Promise 拒绝；失效后清理定时器、页面／消息监听器与文本索引，安全恢复原文，并丢弃迟到结果。正常的临时通信失败不会触发这套失效清理。首次升级到包含本修复的代码时，仍需刷新已打开的网页以替换旧脚本；错误页已有的历史记录可手动「全部清除」。无需为此清除缓存或重新输入 Key。
- **当前区域完成了，但页面底部还是英文**：这是按视口翻译的正常行为。滚动到底部会补译可读内容，包括页脚；处于「仅原文」或已停止状态时不会派发新请求。
- **Key、模型或地址配置错误**：先保存设置，再使用连接测试；测试使用保存后的配置，不会测试尚未保存的输入，也不会发送当前网页正文。
- **只有少数句子没译完**：查看弹窗错误说明并重试失败部分；不满意某段译法时可选择该段右键重译。
- **希望腾出缓存空间**：设置页显示各版本缓存条数及占用，可手动清除。清除无法撤销，但保留 API Key、翻译设置及站点偏好；页面内已显示的译文不会被撤回。

## 项目简介

<img src="icons/icon128.png" width="96" height="96" alt="鹿与地球组成的 DeerWebTranslator 图标">

**版本：1.0.0。** DeerWebTranslator 是使用用户自选大模型进行网页翻译的 Chrome Manifest V3 扩展，采用原生 HTML、CSS 和 JavaScript。

项目追求低干扰的网页阅读体验。当前实现保留原网页元素和真实点击链路，仅更新文字；模型负责结合上下文选择译法，扩展负责文本提取、缓存、协议校验和恢复。它不是 Chrome 内置翻译引擎，也不承诺所有网站都能做到完全一致的布局或翻译质量。

## 页面如何保持原有 UI

默认译文模式通过 `Text.data` 修改文字节点的值，并在内存中记录原值。它不赋值元素的 `innerHTML` 或 `textContent`，不复制按钮、链接、表格或布局容器，不注入定位、宽高、flex/grid 等替代样式。

因此，原有元素、文字节点、属性、图标、伪元素及事件监听器继续存在。译文链接仍是同一个真实链接，默认模式不需要转发点击事件。切回原文时，只有仍属于本次翻译的文字才会被恢复，避免覆盖网站在翻译期间写入的新内容。

界面控件还会检测新增的横向溢出：如果按钮、导航链接等在替换后才发生溢出，就保留原文；原元素没有 `title` 时，提供悬停译文。扩展不缩小字体、不修改控件宽高，也不覆盖网页已有的提示。此保护不能检测所有布局问题，例如自适应控件的自然变宽和多行重排。

段落中的多个文字节点通过固定槽位一起发送给模型。模型可以结合整段语境翻译，但不能移动槽位或修改它们所属的元素。独立链接、按钮、导航、表格等界面文字也会提取；代码、隐藏内容和编辑区域跳过。

双语长段落会额外生成带 `deeptranslate-translation` 类名的译文区域。该区域的链接使用原网页地址，普通点击转发到原链接；依赖真实事件或特殊脚本的站点可能需要切换为默认译文模式。双语模式本身会增加文字长度或页面高度。

## 翻译决策

模型收到的上下文包括页面标题、站点域名、元素类型、页面区域、附近章节标题和同段文字槽位。不发送完整网页 HTML，也不把查询参数作为额外的页面上下文发送。正文中实际出现的地址会尽量以本地占位符保护；规则未识别的地址或配置中出现的地址仍可能发送到所选供应商。

共享翻译策略位于 `src/background/translation-policy.js`：

- 忠实、自然地翻译正文，不解释、不总结、不回答网页中的问题、不添加事实。
- UI 标签优先使用简洁译法，例如“设置”“文档”，避免强制添加英文重复和括号说明撑大控件。
- 技术正文中的术语可按需要保留英文并附简短中文；品牌、项目名、代码符号、命令、路径和版本尽量保持原样。
- GitHub 上的导航操作、README 正文、讨论和仓库元数据按语境区分，保留用户名、仓库名、包名、引用和许可证标识。
- 不需要翻译时原样返回；目标语言、术语表和用户提示词仍参与决策。

清晰的纯 URL、邮箱、常见域名、路径、版本号和哈希在本地过滤。中文目标下，含汉字但不含拉丁字母、西里尔字母、日文假名或韩文的片段会被视为可能已经是中文而跳过；声明为日语或韩语的页面不应用这项跳过规则。这是降低无效请求的启发式规则，并非完整语言检测。

少量无歧义的简体中文界面词（如 Settings、Search、Cancel）可以在本地直接返回，不调用模型。只有默认提示词、无相关术语覆盖时才启用；正文、歧义词和主动重译仍交给模型。没有增加独立的分类、规划或“智能体先思考”请求。

技术领域预设：General、Software、Embedded Systems、Electronics、Audio / DSP、Academic。

术语表示例：

```text
firmware = 固件
latency = 延迟
throughput = 吞吐量
```

推荐每行使用 `原文 = 译文` 或 `原文 → 译文`。后台只发送本批文本或章节标题命中的术语映射，降低长术语表的重复开销；无法识别为映射的自由文本会完整保留，以免丢掉用户规则。

## 速度与 token 开销

- **弹窗并行初始化**：标签页与设置同时读取，页面状态只做 650 毫秒限时探测。打开弹窗不注入网页脚本；点击操作后，仅在确认内容脚本缺失时补注入。按钮操作复用本次弹窗的配置读取，长模型名称不会撑宽窗口。
- **视口按需处理**：预取视口下方约 500 像素、上方约 250 像素内的内容，不在启动时翻译整页屏幕外文本。滚动、展开区域和动态内容变化会触发补译。
- **增量文本索引**：首次分片建立文本节点索引，后续仅检查发生变化的子树。滚动使用 `IntersectionObserver` 提供候选区域，不反复遍历整页文字。索引与提取按小时间片让出主线程，降低页面卡顿。
- **首批较小**：首批目标约 2,200 个源字符，后续批次约 5,000 个源字符，每批最多 24 项，页面最多 3 个批次并发。单项不可拆分时可能略超目标，后台仍有硬性输入上限。
- **动态优先级**：派发前重新按当前视口排序；预取任务不会占满最后一个页面并发槽。标签页隐藏或切到原文时暂停派发，新视口不必等整页队列完成。
- **共享限流**：同一供应商、地址和模型在后台共用并发上限；429 会降低并发并进入冷却，连续成功后逐步恢复，减少多标签页同时请求的拥堵。
- **长文本拆分**：过长文字在请求层按句子／空格边界拆分，返回后合并到原来的文字节点，不新增布局元素。
- **重复文本合并**：同轮发现的相同文字与语义上下文只发送一份；后台也会合并同一标签页、同一任务中同时到达的相同请求。
- **精简协议**：固定提示词去掉重复说明，页面标题限制长度，使用短请求 ID；无独立分类或智能体规划请求。
- **DeepSeek V4 非思考模式**：DeepSeek 适配器对 `deepseek-v4-*` 显式设置 `thinking: { type: "disabled" }`，减少通用翻译中额外的推理等待。其他供应商不会被盲目附加这一参数。参见 [DeepSeek 官方思考模式说明](https://api-docs.deepseek.com/guides/thinking_mode/)。
- **缓存立即回显**：同一批有缓存命中和未命中时，已命中部分先送回页面，不等待模型返回；模型结果通过校验后也立即回显。当前不是逐 token 流式渲染。
- **逐项失败隔离**：可识别且通过校验的 ID 先保存、显示，只重试缺失或损坏的项目。失败不会关闭后续滚动补译；旧页面、旧任务及被重译取代的旧结果不会覆盖新结果。
- **有限重试**：网络错误、超时、429、服务端错误及响应校验失败均限制重试次数；30 秒超时覆盖响应正文读取，429 使用退避。不支持 JSON 模式或温度参数的兼容服务会有限降级，并在本次后台生命周期记住能力。

弹窗用量来自供应商响应，不按字符数猜测，也不折算未经验证的费用。输入、输出及供应商缓存命中 token 分开呈现；后者是输入的一部分，不应再相加。Anthropic 输入包含缓存读取／创建部分，Gemini 输出包含单独报告的思考 token。供应商不返回用量时明确显示缺失；当前为本页本轮统计，不是账户账单或持久化月报。

实际速度和 token 用量取决于模型、网络、页面长度、上下文及供应商。回归测试验证调度、请求合并和协议开销，不代表真实服务商延迟或计费测量。很长的自定义系统提示词、命中的术语及无法解析的自由格式术语规则仍会增加输入 token。

## 供应商与模型

内置适配器的预设来自当前源码，**不是实时模型可用性列表**。模型停用、改名或权限不足时，请选择「自定义模型」并填写供应商实际支持的模型 ID。

| 供应商 | 协议 | 默认 Base URL |
| --- | --- | --- |
| DeepSeek | OpenAI 兼容 | `https://api.deepseek.com` |
| OpenAI | OpenAI 兼容 | `https://api.openai.com/v1` |
| OpenRouter | OpenAI 兼容 | `https://openrouter.ai/api/v1` |
| Anthropic | Messages | `https://api.anthropic.com/v1` |
| Google Gemini | Generate Content | `https://generativelanguage.googleapis.com/v1beta` |
| Moonshot / Kimi | OpenAI 兼容 | `https://api.moonshot.cn/v1` |
| SiliconFlow | OpenAI 兼容 | `https://api.siliconflow.cn/v1` |
| Ollama | OpenAI 兼容 | `http://localhost:11434/v1` |
| 自定义 | OpenAI 兼容 | 用户填写 |

默认 DeepSeek 模型为 `deepseek-v4-flash`。OpenAI 兼容服务在 Base URL 后追加 `/chat/completions`；自定义服务应填写相应的 API 根路径。保存非内置地址时可能需要授予 Chrome 网站访问权限。

Base URL 不接受用户名、密码、查询参数或片段；凭据请填写在独立的 API Key 字段。远程服务应使用 HTTPS，HTTP 不提供传输加密。

Ollama 需要先在本机启动服务并下载所选模型；模型名必须与本机安装一致。云端供应商通常需要独立付费的 API 额度。

## 缓存与输出校验

缓存存储在扩展自己的 `chrome.storage.local`，当前命名空间为 `deerwebtranslator.cache.v7|`。键区分页面 URL、源文本、语义上下文（含章节标题）、页面标题、目标语言、模型、供应商、API 地址、技术领域、系统提示词和相关术语。

后台根据实际输入重新计算哈希。修改相关术语或提示词会得到新的缓存结果；修改未命中的映射不会让无关段落失效。旧命名空间不参与本版查找，但不会自动删除。设置页可以明确清除所有版本的翻译缓存，保留配置和 Key；当前没有自动淘汰历史缓存的机制。

模型返回严格 JSON：

```json
{
  "translations": [
    { "id": "0", "text": "中文译文" }
  ]
}
```

后台验证 ID 对应关系、唯一性、字段、非空文本、受保护网址、槽位完整性与顺序。存在未知／重复 ID 或无法解析的 JSON 时拒绝该次响应；ID 可识别时逐项验证，成功项目不重复请求。非法结果不会作为 HTML 执行；最终失败的段落保留原文，并提供错误说明与重试入口。

## 安全与隐私

- API Key 在设置页输入并保存到本地扩展存储，只有后台请求使用它鉴权。
- 存储访问级别设为 `TRUSTED_CONTEXTS`，内容脚本不读取 Key；网页脚本也不会收到 Key。
- 所选供应商会收到待翻译文本、有限的页面上下文以及相关术语／提示词。请按供应商的数据政策决定是否翻译内部资料。
- 本地存储并非密码保险箱：拥有浏览器配置目录或扩展调试权限的人可能访问设置。不要共享浏览器配置或将设置、缓存、凭据导出到仓库。
- 源码不需要真实 Key。测试使用本地页面、模拟回复和明确的测试凭据，不调用真实模型 API。
- 缓存包含译文，缓存键与站点偏好也可能包含浏览记录线索；只保存在本机，不会上传到本项目的服务器。不要把浏览器配置或扩展存储快照加入 Git。

Manifest 使用 `storage`、`activeTab`、`scripting`、`contextMenus`、内置 API 地址权限及按需授予的自定义 API 地址权限。`contextMenus` 用于选中段落操作。内容脚本声明在普通网页自动加载；翻译由用户操作或用户明确保存的站点自动规则启动。缓存管理和连接测试拒绝网页内容脚本调用。未添加遥测服务。

CSP：`script-src 'self'; object-src 'self'`。不加载远程 JavaScript，不使用内联脚本或 `eval`。

## 已知限制

- Chrome 内部页面、Chrome Web Store 等受保护页面不能注入。
- 当前只处理主页面，未实现跨域 iframe、Shadow DOM、Canvas、图片文字和 PDF 翻译。
- 文字长度变化仍可能导致换行或改变自适应控件宽度；双语模式会主动增加文字量。保留 DOM 不能保证所有页面像素级不变。
- 某些框架会不断重写文字，可能与翻译产生竞争。扩展会丢弃已过期的结果，但复杂站点仍可能需要专门适配。
- 固定文字槽位优先保留原节点关系；跨多段链接和强调标记的复杂句子可能限制译文重排。
- 模型可能误译、误判术语或返回无效 JSON。原样返回只表示本轮无需替换，不保证判断正确。
- 当前缓存没有自动淘汰；旧版本缓存不会被自动删除。
